# EasyLex — איפיון פלטפורמה מוסדית | גרסה 1.1

עדכון בעקבות דוח ההיתכנות. השינויים מגרסה 1.0 מסומנים בכל סעיף רלוונטי.

## עדכונים מרכזיים בגרסה 1.1 (תקציר ההכרעות)

1. **פיצול שלב 0**: שלב 0א (Auth, roles, Rules, onboarding בקודים) ושלב 0ב (כתיבה כפולה של progress + Cloud Function אגרגציה מינימלית). שלב 0ב הוא שער הכניסה לשלב 1.
2. **כתיבת progress לענן: פר-סשן בלבד** (batch אחד בסיום סשן תרגול), לא פר-תשובה. הכרעה סופית.
3. **בדיקות אוטומטיות ל-Security Rules הן תוצר חובה של שלב 0א** — Firebase Emulator Suite + חבילת rules unit-tests. אין שחרור מוסדי בלי שהן עוברות.
4. **הכרעת חמש השאלות הפתוחות** (היו סעיף 8 בגרסה 1.0):
   - כניסה: אימייל+סיסמה בלבד ל-v1. שם משתמש פשוט לילדים — fast-follow.
   - תלמיד בכמה כיתות: נתמך במודל (classIds[]), UX של בורר כיתה יתווסף כשצריך.
   - מודל עסקי: נדחה. שדה plan על מסמך המוסד, נאכף רק ב-UI/Functions, לעולם לא ב-Security Rules.
   - שם תצוגה של תלמיד: פורמט אוטומטי קבוע — שם פרטי + אות משם משפחה ("יוסי כ'"). ללא טקסט חופשי.
   - עריכת באנדים ציבוריים ע"י מורה: אסורה. במקום זאת "שכפל כרשימה מוסדית" (batch copy ל-customLists) ועריכה חופשית שם.
5. **קודי הצטרפות**: אימות קוד עובר דרך Cloud Function עם הגבלת קצב ניסיונות. קודים ניתנים לחידוש.
6. **"זמן אמת" בדשבורד המורה מוגדר כ"עדכני עד דקה"** — לא real-time מילולי. יש לשקף זאת גם במסרים שיווקיים.

## מצבי קצה (חדש בגרסה 1.1 — חובה במימוש)

- **תלמיד עוזב כיתה**: פעולת "עזוב כיתה" בצד תלמיד + הסרה ע"י מורה. מסירים מ-classIds[] ומעדכנים studentCount. ה-progress האישי נשמר אצל התלמיד; המורה מפסיק לראות אותו.
- **תלמיד חוזר להיות עצמאי** (עוזב את כל הכיתות): institutionId מתאפס, הסנכרון חוזר להתנהגות עצמאי (כל הרשימות הציבוריות). ההתקדמות נשמרת.
- **מורה עוזב מוסד**: כיתותיו מסומנות "ללא מורה" וממתינות לשיוך מחדש ע"י המנהל. לא נמחקות.
- **מחיקת כיתה**: ארכוב רך (archived=true) כברירת מחדל; מחיקה פיזית רק ע"י Cloud Function ייעודית (אין cascading delete ב-Firestore).
- **השבתת מוסד**: שדה status על המוסד; מוסד מושבת — מורים ומנהל מאבדים גישה, תלמידים הופכים אוטומטית לעצמאיים בפועל.
- **עריכת משימה אחרי תחילת תרגול**: מותרת הוספת מילים; הסרת מילים לא מוחקת progress קיים (המסמכים נשארים, פשוט לא נספרים במשימה).
- **מיגרציית ה-admin הקיים**: מסמך המשתמש עם role="admin" מומר חד-פעמית ל-role="superadmin" (משימה 0.1).
